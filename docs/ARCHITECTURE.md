# Архітектура сайту: механіки окремо, інструменти їх комбінують

Основна ідея Zbyrai: **головні механіки живуть окремо, кожна у своїй папці**, а генератори, симулятори й ігри сайту беруть або одну механіку окремо, або поєднання двох-трьох.

## Правила
1. Одна механіка = одна папка `mechanics/<назва>/` з чітким інтерфейсом (`index.js`), даними (`data.js`), тестами (`test/`) і коротким `README.md` (що робить, вхід/вихід, формат даних).
2. Механіка **не знає про інструменти**: ні про DOM, ні про `localStorage`, ні про конкретну гру. Лише чиста логіка й дані; детермінована від зерна (`seed`), де є випадковість.
3. Механіка може залежати від інших механік лише через їхній `index.js`; цикли заборонені.
4. Інструмент (`<інструмент>/`) лише **комбінує** механіки: тримає стан, UI, збереження, малювання. Логіки економіки/будівництва/NPC в інструменті бути не повинно.
5. Зміна формату даних механіки: версія в README механіки й запис у [data-versions.md](data-versions.md).
6. Файли малі (див. [file-rules.md](file-rules.md)); нова можливість = новий файл у папці механіки.
7. Модуль працює і в браузері (глобал `Mech.<Назва>` через `<script>`), і в Node (`module.exports`).

## Нові механіки
Кладуться в `mechanics/<назва>/`. Перші в цій папці (для гри «Будівництво міста»):
| Папка | Що |
|---|---|
| `mechanics/world-lite/` | малий материк: ландшафт, біоми, поселення, дороги, лігва загроз |
| `mechanics/trade/` | ціни, потреби/виробництво поселень, каравани, засідки |
| `mechanics/building/` | типи будівель, розміщення, дороги навколо, знос і прибирання доріг, виробництво |
| `mechanics/settlers/` | прибульці, житло, професії, настрій, стосунки (на основі `colonist-foundry`) |

Інструменти-комбінатори: `city-builder/` (усі чотири).

## Як додати механіку
1. Папка `mechanics/<назва>/` з `index.js`, `README.md`, `test/`.
2. Додайте рядок у таблицю вище й у [NAVIGATION.md](NAVIGATION.md).
3. Підключайте з інструментів лише через публічний інтерфейс.
