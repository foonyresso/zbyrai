# Відео редактор і конвертер: карта й рішення

Що тут: як влаштований `video-editor/`, де що лежить, що вже зроблено (етап 1) і що далі (етап 2). Користувацький опис: [../video-editor/README.md](../video-editor/README.md).

## Модель
Відео = список частин `segs = [{ s, e, speed, vol }]` (початок і кінець в оригіналі, швидкість 0,1…8, гучність 0…2). Час на таймлайні (вихідний) = сума `(e-s)/speed`. Усі правки (розрізати, видалити діапазон, лишити діапазон, змінити швидкість чи гучність діапазону) це чисті функції в `ve-core.js`; діапазон спершу «виокремлюється» (`isolate`), тобто розрізається по краях. Кадр: рамка `crop` у пікселях оригіналу або `null` (весь кадр). Історія: знімки JSON (до 120), швидкі повзунки зливаються в один крок.

## Експорт
Одна команда ffmpeg: для кожної частини `trim` + `setpts` (відео) і `atrim` + `asetpts` + `atempo` + `volume` (звук), далі `concat`, `crop`, `scale`, `format=yuv420p`, загальна `volume`. GIF: `fps` + `palettegen`/`paletteuse`. MP3: лише звук. `atempo` ділиться ланцюжком для швидкостей поза 0,5…2. Прогрес береться з рядків `time=` журналу ffmpeg, скасування знищує воркер (ядро лишається в пам'яті сторінки).

## Рішення й обмеження
- Одно-потокове ядро: не потрібні заголовки COOP/COEP, працює на звичайному Cloudflare Pages. Повільніше за багатопотокове; 4K і довгі відео обробляються довго, пам'ять сторінки до ~2 ГБ.
- Ядро (≈32 МБ) не лежить у репозиторії: перевищує ліміт 25 МБ файлу Cloudflare Pages. Завантажується з jsdelivr/unpkg при першому експорті; потрібен інтернет при першому запуску, далі кеш браузера.
- Експорт і завантаження результату лежать у нижній панелі й меню «Експорт» (за UI-кітом, верхня панель містить лише назву, «i» і повернення). Проєкт (JSON) не зберігається: джерело відео лишається лише у файлі користувача.
- `file://` не підтримується (воркер модулів), потрібне http(s).
- Формат JSON відсутній, тому `data-versions.md` без змін.
