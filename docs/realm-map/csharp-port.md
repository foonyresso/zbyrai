# Перенесення в Godot C#

Файл інструмента в грі не використовується: переноситься **механіка**. Нижче: що з чим збігається і на що зважати.

## Відповідність файлів

| JS (`realm-map/`) | C#-аналог |
|---|---|
| `core/rng.js` | `Rng` (mulberry32 на `uint`, `unchecked`), `Stream(seed, name)` |
| `core/noise.js` | `PerlinNoise` (таблиця з перемішаного масиву за зерном), працюйте з `double` |
| `core/heap.js` | `PriorityQueue<int, double>` з .NET 6+ |
| `core/grid.js` | `Grid` (клас із `float[] Vx, Vy, Cx, Cy`, методи `Neighbors`, `Components`, `DistanceField`) |
| `core/terrain.js`, `climate.js`, `rivers.js` | `TerrainGen`, `ClimateGen`, `RiverGen` |
| `core/politics.js` | `PoliticsGen`: `Flood` це один метод Дейкстри з мітками |
| `core/settlements.js`, `pois.js`, `lairs.js` | `SettlementGen`, `PoiGen`, `LairGen` |
| `core/router.js`, `roads.js`, `searoutes.js` | `Router` (Дейкстра з множинними цілями), `RoadGen`, `SeaRouteGen` |
| `core/planner.js` | `TravelPlanner` |
| `data/*.js` | статичні класи або ресурси Godot (`.tres`/JSON); текст бестіарію без змін |

## Структури даних

- Всі шари світу — плоскі масиви (`byte[]`, `float[]`, `int[]`), індекс `y * w + x`. Біоми, ранги, стани — `enum`.
- `Settlement`, `Poi`, `Lair`, `Road`, `SeaRoute`, `Province`, `Region` — прості `record`/`class` з полями, що збігаються з JSON експорту (`worldToJSON`): його можна десеріалізувати напряму й використати як еталон перевірки.
- Замикання з `R.Data` замінити локальними функціями/делегатами.

## Пастки (знайдені під час розробки)

1. **Дейкстра на `float`**: порівняння `d > best[c]`, де ключ купи `double`, а `best` — `float`, відкидало вузли й ламало маршрути. Використовуйте `double` скрізь, де це відстані. Висоти й вологість можна `float`.
2. **Нестабільне сортування**: `List.Sort` у C# нестабільне, `Array.sort` у JS стабільне. У коді всі сортування мають вторинний ключ (індекс), зберігайте його.
3. **Порядок обходу**: `Map`/`Set` у JS зберігають порядок вставки; `Dictionary`/`HashSet` у C# не гарантують. Там, де порядок впливає на результат (ребра MST, списки), використовуйте `List` або `SortedDictionary`.
4. **Збіг із JS бітами** не потрібен і малоймовірний (різна арифметика). Мета: ті самі правила, а не та сама карта. Експорт `worldToJSON` дає еталонні значення для ручних перевірок.
5. **Продуктивність**: генерація середньої карти ~0.3 с у JS. У C# на потоці світу це мілісекунди; великі світи можна генерувати чанками за регіонами (всі стадії від 8 і далі працюють по регіонах).

## Інтеграція з іграми

- Зберігайте в збереженні лише `seed` + параметри + список змін (занепад, захоплення монстрами); карта відновлюється.
- Місто всередині: використовуйте `Settlement.Id` і зерно `seed|city|id` для генератора міст ([medieval-world](../../medieval-world/)).
- Лігва й боси мають `Tier`, `Radius` і зачіпку: готові вхідні дані для квестів і спавну.
