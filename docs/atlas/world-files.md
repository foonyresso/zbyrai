# Файли світів (формати 1 і 2)

Кожен світ Атласу лежить в окремому файлі `medieval-world/worlds/<id>/world.js` і сам себе реєструє. Ядро (`src/core/atlas.js`, `src/ui/world-kinds.js`) нічого не знає про конкретні світи: меню «Світ» угорі будується з реєстру. Додати світ: створити папку й файл, запустити `node tools/build-atlas-registry.mjs` (оновить `medieval-world/registry.js`, бо сайт статичний), перевірити `node tools/atlas-registry.test.js`. Основний генератор переписувати не треба.

Версії: **1** (початковий) і **2**, що лише додає необов'язкове поле `lore` (повний опис світу для гри). Файли формату 1 працюють без змін; інший формат відхиляється. Нові світи пишемо у форматі 2.

## Шаблон

```js
Atlas.registerWorld({
  format: 2,                       // версія формату файлу: 1 або 2 (обов'язково)
  id: "my-world",                  // = назві папки; латиниця, цифри, дефіс
  name: "Мій світ",                // назва в меню
  order: 30,                       // порядок у меню (менше = вище)
  runner: "iframe",                // "builtin" (основне полотно Атласу) або "iframe" (власна сторінка)
  entry: "worlds/my-world/index.html?embed=1", // для iframe: сторінка світу (шлях від medieval-world/)
  description: "Короткий опис для підказки меню.",
  biomes: { allow: ["grass", "my-biome"] }, // які біоми дозволені світу (див. biome-files.md)
  lore: { /* повний опис для гри, див. нижче */ },
});
```

## Поля

| Поле | Обов'язкове | Про що |
|---|---|---|
| `format` | так | Поки що `1`. Інше значення відхиляється |
| `id`, `name`, `runner` | так | `runner: "builtin"` лише для нескінченного світу; решта світів `iframe` |
| `order` | ні (100) | Порядок у меню |
| `default` | ні | `true` рівно в одного світу: він відкривається першим (тест перевіряє) |
| `entry` | для iframe | Сторінка світу. З `?embed=1` вона ховає власну шапку: верхню панель показує Атлас |
| `preset` | ні | Об'єкт параметрів, з яких світ стартує (для світів на рушії «Материк» це його параметри: `worldType`, `size`, `provinces`, `warm`, `wet`, `ruggedness`, `theme`... Тему оформлення див. [continent/themes.md](continent/themes.md)). Застосовується при першому відкритті світу; далі світ береже власні параметри |
| `inherit` | ні | `id` іншого світу, від якого беруться `extraActions` і `titles` (щоб не копіювати) |
| `extraActions` | ні | Додаткові кнопки верхньої панелі: `{ id, label, title }`; `id` — кнопка в сторінці світу, яку натискає Атлас |
| `titles` | ні | Підказки кнопок «Імпорт/Посилання/Копіювати JSON/Зберегти .json/Зберегти PNG» для цього світу |
| `biomes` | ні | Правила біомів: `allow`, `deny`, `weights`. Біоми окремих світів мають тег `exclusive`: старі світи пишуть `deny: "tag:exclusive"` |
| `lore` | ні (формат 2) | Повний опис світу для гри, див. розділ «Поле lore» |

## Поле `lore` (формат 2)

Пишеться навіть для того, чого генератор поки не вміє: гру з цього генератора переноситимуть у Godot, і всі світи треба відтворити. Усі поля необов'язкові, але для готового світу бажано заповнити їх усі (тест перевіряє основні).

| Поле | Про що |
|---|---|
| `ref` | Номер світу в списку автора (рядок) |
| `subtitle` | Підзаголовок: «Світ дерев заввишки з гору» |
| `concept`, `meaning`, `history` | Концепт, сенс, походження та історія |
| `structure`, `sky` | Просторова структура й небо |
| `biomes[]` | Біоми світу: `{ id, as_name?, note? }`. `id` — файл біома (нові або наявні); `as_name` — назва в цьому світі, якщо наявний біом перейменовано (щоб не створювати дубль) |
| `creatures[]`, `bosses[]` | id монстрів і босів із `monsters/` (у них `spawn.worlds` має містити цей світ) |
| `architecture[]`, `locations[]` | Архітектура; ключові локації й унікальні місця |
| `mechanics[]` | Унікальні механіки й закони світу |
| `resources[]` | Ресурси |
| `exploration` | Як гравець досліджує світ |
| `visual` | `{ style, palette: [{ hex, name }], atmosphere, signature }`: стиль, палітра, ефекти й головна візуальна особливість |
| `structures` | `{ under: [], above: [] }`: підземні й надземні споруди (підземелля, літаючі острови, мости, вежі) |
| `dungeons[]` | id підземель із `dungeons/` для цього світу (спільні або власні) |
| `game[]` | Нотатки для перенесення в гру (реалізація механік, сцени) |
| `implemented` | Що з цього вже видно в генераторі |
| довільні `geology`, `effects`, `dangers`... | Додаткові поля, якщо в концепті автора є такі розділи; ядро їх не читає |

Вигляд у генераторі: `preset.theme` + біоми (див. [continent/themes.md](continent/themes.md)). Монстри й підземелля нових світів поки не показуються на карті «Материка» (рушій має власні списки); їх відтворить гра.

## Світ у iframe: що має вміти сторінка

Сторінка отримує `?embed=1` і слухає `postMessage` від Атласу: `atlas-click` (натиснути кнопку за `id`), `atlas-import` (текст JSON), `atlas-link` (віддати параметри для посилання). Зразок: `worlds/continent/ui/embed.js`. Посилання на світ: `#w=<id>&p=<параметри>`.

## Наявні світи

| Світ | Файл | Що |
|---|---|---|
| Нескінченний (стандарт) | `worlds/infinite/world.js` | основне полотно, відкривається першим |
| Материк | `worlds/continent/world.js` | скінченна карта королівств; код у цій же папці |
| Архіпелаг, Один острів, Суходіл із морями | `worlds/{archipelago,island,pangea}/world.js` | зразки: той самий рушій з іншими параметрами |
| Астракор (131), Останки (132), Кровостеп (133), Вершинниця (134), Неборід (135), Міднокрил (116) | `worlds/{astrakor,ostanky,krovostep,vershynnytsia,neborid,midnokryl}/world.js` | формат 2: повний опис у `lore`, власні біоми, монстри, боси й підземелля; вигляд — власні теми на рушії «Материк» |
